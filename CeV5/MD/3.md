
MERCWAR DISTRIBUTED OPEN API SPECIFICATIONS

Specification Standard: RESTful JSON & Asynchronous File Stream Endpoints
Target Matrix: Multi-Tenant Execution Runtimes (AVIS-DL, Eclipse, Stargate)

Architectural Paradigm

The Mercwar server infrastructure treats its core platform as a decentralized Open API. The architecture allows developers to bypass restrictive gateways by providing client-side JavaScript applications direct, unhindered consumption of the underlying server-side PHP microservices (NEXUS, STARGATE, Cron).
Developers write and publish front-end scripts directly onto the ecosystem origin. The servers recognize these deployments as natively authorized applications, enabling arbitrary external data synchronization, storage allocation, and runtime script interactions.
 [ Client Layer (User-Written JavaScript) ] 
       │
       ├──( POST Multi-Asset )──► /AVIS-DL/ (Stores HTML, JS, CSS, JSON for free)
       ├──( GET/POST Scripts )──► /eclipse/ & /cron/ (Executes open PHP backend files)
       └──( Cross-Lake Sync )──► /stargate/ (Instant origin bridge to remote data lakes)

API Endpoint Catalog


1. AVIS DataLake Application Storage Engine (AVIS-DL)

• Endpoint / URI: http://byethost3.com
• Method: POST
• Access Level: Open API (No Core Authentication Required)
• Description: Ingests and stores arbitrary client-side application assets to be served back over the web origin. Unlike static metrics engines, AVIS-DL allows the storage of complete web application file extensions to form standalone web clients.
• Supported MIME Types: text/html, application/javascript, text/css, application/json.
• Payload Format (multipart/form-data):http
POST /AVIS-DL/upload.php HTTP/1.1
Host: mercwar01.byethost3.com
Content-Type: multipart/form-data; boundary=----WebKitFormBoundary

------WebKitFormBoundary
Content-Disposition: form-data; name="app_file"; filename="custom_agent.js"
Content-Type: application/javascript

// User client-side application code sits here...
------WebKitFormBoundary--
Use code with caution.
• Expected Response (201 Created):json
{
  "status": "success",
  "resource_path": "/AVIS-DL/vault/custom_agent.js",
  "serving_origin": "http://mercwar01.byethost3.com",
  "access": "public_served"
}
Use code with caution.

2. New Eclipse PHP Sandbox Core

• Endpoint / URI: http://byethost3.com
• Method: POST | GET
• Access Level: Open PHP Runtime Matrix
• Description: Provides programmatic execution layers where user frontends hook straight into unmapped PHP functions. It links incoming client events directly to backend runtime hooks without demanding root administrative access.
• Payload Fields (application/json):json
{
  "routine_target": "NEXUS_MODEL_PIPELINE",
  "action_statement": "STREAM_TRANSCRIPT",
  "payload_buffer": "string_data"
}
Use code with caution.
• Expected Response (200 OK): Reflects live processed results piped directly out of the root NEXUS automation ruleset.

3. Stargate Instant HTML Origin Bridge

• Endpoint / URI: http://byethost3.com
• Method: POST
• Access Level: Instant Origin Access (Zero-Cost / Free)
• Description: A specialized network wrapper facilitating raw hypermedia handshakes. It allows a JavaScript application running locally or remotely to use the Mercwar host environment as an instant routing bridge. Frontends consume this route to push or pull data arrays to other external datalakes completely free of origin blocks.
• Payload Fields (application/json):json
{
  "stargate_op": "CROSS_LAKE_SYNC",
  "destination_lake_uri": "https://remote-datalake-node.net",
  "payload_manifest": { "origin_data": "..." }
}
Use code with caution.
• Expected Response (200 OK):json
{
  "bridge_state": "connected",
  "tunnel_id": "stargate-uuid-string",
  "transfer_status": "acknowledged"
}
Use code with caution.

4. Cron / Blogger Open Automation Layer

• Endpoint / URI: http://byethost3.com
• Method: GET
• Access Level: Open API Gateway
• Description: An unauthenticated tracking gateway that triggers chronologically driven tasks or exposes open layout updates. Custom developer tools issue simple request strings to this endpoint to poll, fetch, or append public records.
• Query Parameters (GET): ?action=fetch_latest_blog&sub_system=fire
• Expected Response (200 OK): Emits a structured array containing raw telemetry feeds or string streams.

Security Separation Architecture Matrix

The network enforces a deliberate security boundary between the multi-tenant development pipeline and its structural root identities:

Environment Area	Authentication Method	API State	Intended Operational Use
AVIS-DL Storage	None (Anonymous Open Gate)	Live & Served	Storing custom JS, HTML frontend modules, and templates.
Stargate Bridge	None (Zero-Cost / Free)	Live & Served	Instant cross-origin synchronization with remote data lakes.
Cron & Blogger	None (Open Web Layer)	Live & Served	Fetching public logging strings and background scripting routines.
Mercwar AI Origin	Strict Security Login Form	Protected Gate	Root server settings and global architecture management.
GitHub Matrix	Secure Cryptographic Keys	Immutable Baseline	Core engine storage, NEXUS SDK builds, and system laws.
